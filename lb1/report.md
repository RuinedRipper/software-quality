## Відповіді на контрольні питання

1. **Що розуміють під якістю програмного продукту?**
Якість — це наскільки продукт відповідає вимогам і очікуванням користувачів. Вона охоплює функціональність, надійність, продуктивність, зручність, безпеку та інші характеристики.

2. **Чому факт працездатності програми ще не означає її високої якості?**
Програма може запускатися, але працювати повільно, мати помилки в окремих сценаріях, бути незручною або небезпечною. Працездатність — лише одна зі складових якості.

3. **Що таке аномалія?**
Це поведінка системи, яка відрізняється від очікуваної і потребує подальшого аналізу.

4. **Чому аномалія не завжди є дефектом?**
Після аналізу вона може виявитися хибним спрацюванням (false positive), запитом на зміну (change request) або передбаченою поведінкою. Наприклад, locked_out_user не може увійти, бо цей акаунт заблокований навмисно.

5. **Що таке Expected Result та Actual Result?**
Expected Result — як система мала б працювати згідно з вимогами та логікою. Actual Result — як вона працює насправді.

7. **Для чого потрібен defect report?**
Щоб інша людина змогла зрозуміти проблему, відтворити її, проаналізувати та виправити.

8. **Яку інформацію повинен містити defect report?**
Title, test object і test environment, контекст, кроки відтворення, Expected Result, Actual Result, докази (скриншоти, відео, логи), Severity, Priority, Status і посилання.

9. **Для чого використовуються GitHub Issues?**
Для реєстрації та відстеження аномалій і дефектів. Кожна проблема отримує окремий запис з описом, вкладеннями та коментарями.

10. **Навіщо до Issue додавати screenshot або відеозапис?**
Це наочний доказ, який допомагає побачити й відтворити проблему. Скриншот підходить для візуальних проблем, а відео для динамічних (затримки, послідовність дій).

11. **Чим Severity відрізняється від Priority?**
Severity показує, наскільки серйозно дефект впливає на систему й користувачів. Priority показує, наскільки терміново його потрібно виправити.

12. **Для чого у defect report вказують test environment?**
Дефект може проявлятися лише в певній ОС, браузері чи версії. Знаючи середовище, розробник зможе відтворити проблему.
